The problem

The expensive failures are not bad code

On a three-person team all running Claude Code, Codex, or OpenCode against one repo: two people building the same thing, two branches rewriting the same file, two migrations racing the same table.

The obvious fix — share the chats — is the wrong fix. Prompts and model output are the most private thing a developer produces.

Conductor never shares prompts or output — only intent and territory.

Features

One command to check, everything else to trust the answer

That is the whole product in one command. Everything else exists to make that answer correct, fast, and safe to trust.

Conflict check

Run before you edit. Exit 3 means stop: someone holds your territory.

$ conductor check --summary "…" --scope dir:internal/api

block_conflict: scope conflict on dir:internal/router

  alice holds dir:internal/router for T-1 (write_exclusive).
  Wait for it, split your scope, or join their task.

Semantic duplicate detection

Two people describing the same work in different words, with no overlapping files yet. Both summaries are reduced to HMAC’d token sets under a per-tenant key and compared with MinHash. Detection without disclosure. 

$ conductor check --summary "Build team invitation flow"

suggest_join: similar work already in flight

  T-3 (owner alice) looks like the same work.
  Join it, or narrow your scope.

Capability-aware dispatch

A session advertises what it is driving; the catalog decides what that is worth. A floor is a floor: an idle cheap session never wins a selection it does not qualify for. 

$ conductor task assign T-42 --require-tier T4 --require-effort xhigh

T-42 offered to alice (claude-opus-5 on claude).
  requirement: tier ≥ T4, effort ≥ xhigh
  1 of 3 live session(s) qualified

$ conductor policy lint

  0 error(s), 1 warning(s).

Transferable budgets

Every member gets the same token allowance over a rolling 30-day window — and it is transferable, with no admin in the loop. Balances are pure arithmetic over two ledgers, so there is no counter to drift and no way to mint tokens. 

$ conductor budget share bob 2m --note "finishing the router refactor"

Shared 2m tokens with bob.

  you    1.1m remaining
  bob    3.4m remaining

Swarm and admission queue

Coworkers join the same control plane and their machines and sessions become shared capacity. Past the caps, new work takes a place in line instead of failing. 

$ conductor swarm

Capacity: 2 runner(s), 3 session(s) accepting work,
          5 free slot(s), 1 waiting in queue

concurrency:
  max_active_sessions: 6
  max_sessions_per_principal: 2
  max_concurrent_attempts: 4

Pause, resume, and measure

One command freezes every agent terminal on the machine; one command wakes them. Every harness meters itself; Conductor reads those logs and keeps one ledger. What crosses the wire is numbers, a model name, and an hour. 

$ conductor pause     # freeze every interactive agent session
$ conductor resume    # wake them; closed terminals are reopened

$ conductor usage --by day,harness
$ conductor budget    # the team's token budget this window

Architecture

How it holds together

Ledger, leases, reservations, conflict graph, presence — on Postgres as the source of truth. Four mechanisms do the real work: transactional claims, fencing epochs, reservations under an advisory lock, and merge risk from observed diffs.
